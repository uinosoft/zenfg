adapter exposes 16 storage buffers per shader stage; the migrated host requests
only 8. All native pipelines were created and all four rendering modes executed
under that requested limit. Exact GPU model and driver identifiers were not
exposed by the browser.

bit-identical parallel simulation. Long-running numerical convergence and a
full visual sweep of every advanced optical parameter were not measured.

## Automated coverage

The root test runner includes this workspace. Tests use the real FrameGraph
compiler and fake GPU encode callbacks to cover branch dependencies, roots,
culling, initialized byte ranges, odd/even iterations, first/stable/paused frames,
drag indices, pouring, abandoned recordings, compile/encode/submit failures,
pending readback reset, resource pool specification changes, capacity rejection,
initialization cancellation, and repeated disposal.

Scene and shader source hashes are checked against the pinned upstream. Fixed
expected injection bytes and time-bank sequences were generated by running the
original source, independently of the migration. The fixtures cover nozzle
geometry, jitter, gravity, budget exhaustion, varied frame gaps, time scales,
and substep counts. Fake GPU tests do not execute WGSL.

Required repository checks:

```sh
npm run typecheck
npm test
npm run build:pages
npm run docs:check
```

All four commands passed. After rebasing onto main `0ea2efc`, the root suite
passed 510 tests. The assembled
Pages build was also opened in the browser and rendered the default scene with
its bundled environment and no WebGPU validation errors. Vite reported the
existing large-chunk warning for shared Inspector/highlighter dependencies.

The rebased checkout was also verified with `npm run dev:playground` on port
5175 after `npm install` restored the new workspace package link. The default
fluid scene and environment loaded, Inspector captured real frames with GPU
timing and zero diagnostics, and switching to Minimal Frame and back refreshed
the capture correctly. The JavaScript shader source tab rendered with syntax
highlighting.

## Diagnostic attribution regression

The resource-attribution refactor was compared with the previous implementation
for all four display modes, each on first, stable, and paused frames (12 cases).
Normalized node/access/dependency/root/resource reports, physical sharing groups,
and encoded pass/dispatch/draw/clear/copy sequences matched. Resource and group
IDs were normalized by stable labels; diagnostic metadata was excluded from
the comparison. This isolates grouping from later access-range corrections.

## Example access and inspection refinement

The subsequent example-only revision passed the four repository commands above
in sequence, with **522 tests** passing. No Inspector, compiler, public API,
Snapshot protocol, or vendored shader changes were made.

New real-compiler/fake-device regressions check stage attribution in all four
modes, deduplicated shared imports, active render ranges after pouring, and
cross-stage transient reuse. Scan cases use 1 and 343 cells, covering minimum
allocation padding and a partial 256-thread workgroup. They import cell starts
with undefined contents, verify overwrite of exactly the generated prefixes,
check that later scans retain ordering without consuming earlier scan values,
and reject an added consumer of the unwritten padding word. Sparse rigid-body
writes still preserve prior contents. Existing functional and transaction tests
continue to cover pause, parity, drag, filtering, and failed-recording recovery.

The user-provided frame-5 snapshot was compared with a new snapshot generated by
the real compiler and fake GPU at the same topology settings: Small, SSFR,
1216 × 919 viewport, two advancing substeps, four constraint iterations, and
the preset filters. Counts below use the existing Inspector's
`createDebugViewModel()` and `createGraphScene()` functions. The new capture is
a stable frame after initialization; this is a topology comparison, not the
same simulation instant or a GPU performance benchmark.

The existing prediction-buffer/SSFR-anisotropy physical sharing remains across
Simulation and Render. Scan-block storage can also share with packed solids in
this configuration. Removing redundant scan-block clears changes clear commands
only in this second revision; compute dispatches and graph nodes are retained.

The running Playground was checked again after the final code changes. All four
Small rendering modes displayed water and solids, SSFR pouring exhausted the
30,000-particle budget, and new real-frame captures reported zero errors and
zero warnings. Browser error logs were empty. Pass and Group Hierarchy views
showed the revised scopes and retained rigid-projection node timing. The folded
graph showed the workload group, external backbuffer, and root endpoints instead
of a separate column of all workload resources. This pass did not repeat the
earlier upstream visual comparison or broaden the hardware coverage.

Full expansion remains dense: 143 visible nodes and 381 edges in the fixed
comparison. Long labels, repeated solver iterations, and following cross-stage
relationships still require navigation. Breadcrumbs, stage focus, and relation
summaries remain separate proposals in the
[debugging review](../../docs/particles4all-debugging-review.md); acceptance of
this example revision does not depend on them.

## Remaining hardware coverage

Intel/AMD adapters, Apple/Metal, mobile devices, other browser engines, and a
physical adapter whose maximum is exactly eight storage buffers were not
available in this run. Eight-, ten-, and sixteen-buffer capability configurations
are covered by fake-device tests. Device loss, delayed maps, cancellation, and
environment request races are deterministically covered there; no physical
device-loss event was forced during the browser session.
